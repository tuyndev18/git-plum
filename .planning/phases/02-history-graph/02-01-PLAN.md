`git log --all --topo-order --format=%H%x1f%P%x1e | wc -c` (đây là lệnh mà plan 02-02 sẽ
phân tích, nên con số này là mốc so sánh).

**Ràng buộc bắt buộc: mỗi commit phải thay đổi nội dung tệp — tree phải khác cha.**

Lý do, đã kiểm chứng bằng thực nghiệm trên git 2.54.0.windows.1:

```
# Merge có tree TRÙNG một cha
git rev-list --all --count        → 3
git log --all --format=%H | wc -l → 2      ← commit merge BỊ LƯỢC
git log --all --format=%P | grep -c ' ' → 0  ← cổng đếm merge trả 0 dù repo CÓ merge

# Merge có tree KHÁC cả hai cha
git rev-list --all --count        → 4
git log --all --format=%H | wc -l → 4      ← khớp
git log --all --format=%P | grep -c ' ' → 1  ← đúng
```

`git log` mặc định áp *history simplification* và lược commit có tree trùng một cha. `--sparse`,
`--full-history`, `--boundary`, `-m` **đều không** cứu được — đã thử cả bốn. Nếu script sinh ra
commit không đổi nội dung (ví dụ merge chỉ để tạo hình dạng, không sửa tệp nào), repo sẽ hợp lệ
nhưng cổng verify trả 0 và Task này thất bại theo cách không giải thích được.

Vì vậy: mọi commit, **kể cả commit merge**, phải ghi hoặc sửa ít nhất một tệp. Ghi ràng buộc
này thành comment trong chính script.

**Hệ quả cho cổng verify:** dùng `git rev-list --all --format=%P` (lọc dòng `^commit `) để đếm
merge, không dùng `git log`. `rev-list` không áp simplification. Và cổng có thêm một điều kiện
khẳng định `rev-list --all --count` **bằng** số dòng `git log --all --topo-order` — nếu hai số
lệch nhau thì script đã sinh ra commit bị lược, phải sửa script chứ không sửa cổng.

**Luồng `git fast-import` — cảnh báo về `data <n>`.**

`data <n>` đếm **byte**, không đếm ký tự. Script bash sinh nội dung động rất dễ lệch một byte
(newline cuối, ký tự đa byte UTF-8, `\r` trên Windows). Khi lệch, fast-import thất bại theo
cách vô dụng:

```
fatal: unsupported command:
fast-import: dumping crash report to .git/fast_import_crash_18280
```

Không nói byte nào sai, không nói dòng nào. Vì vậy:

1. Đưa vào script một khối mẫu tối thiểu **đã kiểm** và giữ nguyên hình dạng đó khi mở rộng.
2. Tính `n` bằng `printf '%s' "$content" | wc -c`, **không** đếm bằng `${#content}` (đếm ký tự).
3. **Chạy thử luồng 5 commit trước khi chạy 100k.** Thất bại ở 5 commit mất một giây; thất bại
   ở 100k commit mất nhiều phút và vẫn không biết sai đâu.

Ghi vào README: số commit thật sinh ra, thời gian sinh, và cảnh báo rằng script này mất
nhiều phút và chiếm dung lượng đĩa đáng kể, nên **không** chạy trong CI mặc định.
